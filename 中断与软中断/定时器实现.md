
# Linux-2.6.12

## 基本概念

添加一个定时任务，定时任务会在软中断中执行.

## 数据结构

参见 timer.dia .

### tvec_base_s

定时器管理最上层结构体，PER_CPU 变量.

定时器按照触发时间先后顺序分别存储在 tv1、tv2、tv3、tv4、tv5 中.

### tvec_root_t

`tvec_base_s` 中声明了 tv1 结构体成员.

用于挂载最近要触发的定时器.

### tvec_t

`tvec_base_s` 中声明了 tv2、tv3、tv4、tv5 结构体成员.

用于挂载时间较远触发的定时器.

### timer_list

表示一个定时器结构体.

其中包括到时时要执行的函数、函数参数等.

## API接口

| API            | 说明                                   |
|----------------|----------------------------------------|
| init_timer     | 定时器初始化                           |
| add_timer      | 添加定时器                             |
| mod_timer      | 修改定时器超时时间                     |
| del_timer      | 删除定时器，在链表中返回1 ，否则返回 0 |
| del_timer_sync | 删除定时器，等待执行解释               |

## 核心算法

### 定时器管理

参见 timer.drawio::timer_idx .

定时器被添加在了 tv1、tv2、tv3、tv4、tv5 几个队列中，其中tv1 精度最高，其他精度递减.

每个队列中，是一个**滚动数组**.

可以通过 [算法调试程序](#算法调试程序) 查看定时器最终添加到哪个队列中.

如示例所示，expires == 256 的定时器，timer_jiffies == 0 时，最开始被加入到 tv2[1] 中.
随着timer_jiffies 增加，expires == 256 的定时器会被加入到 tv1[0] 中.

当tv1 循环执行结束，重新回到 index == 0 处的时候，expire == 256 的定时器可能存在
于tv1[0]，也可能存在于tv2[1]，所以此时需要 `cascade()` 函数，将tv2[1] 中的定时器重新
添加到tv1 中.

## 常见疑问

- `timer->magic = TIMER_MAGIC;` 这句的作用？

  因为定时器是异步调用的，如果没有正常初始化会在软中断中执行，不仅不容易发现而且
  容易造成设备死机.

  添加TIMER_MAGIC 检测，可以在处于定时器添加上下文时就能及时发现问题.

- 链表中定时器如何移动？

  通过`cascade()` 函数，每次执行到 index == 0 的时候，都需要处理上级的级联关系.

  ```c
	if (!index &&
		(!cascade(base, &base->tv2, INDEX(0))) &&
			(!cascade(base, &base->tv3, INDEX(1))) &&
				!cascade(base, &base->tv4, INDEX(2)))
		cascade(base, &base->tv5, INDEX(3));
  ```

- 需要处理多级级联的时候，tv1-tv2 ，tv2-tv3 之间，应该先处理哪一个？

  这里的级联关系其实先处理哪一层都没有关系，因为最终都是调用 internal_add_timer() 函数，
  会重新添加下个槽位中的定时器.

- 定时器中内存屏障的使用

  参见 内存屏障实例，此处的内存屏障实现实际有问题.

### 算法调试程序

```c
#include <stdio.h>
#include <string.h>

#define TVN_BITS (6)
#define TVR_BITS (8)
#define TVN_SIZE (1 << TVN_BITS)
#define TVR_SIZE (1 << TVR_BITS)
#define TVN_MASK (TVN_SIZE - 1)
#define TVR_MASK (TVR_SIZE - 1)


static void internal_add_timer(unsigned long timer_jiffies, unsigned long expires)
{
	int i, vec;
	unsigned long idx = expires - timer_jiffies;

	printf("timer_jiffies %lu expires %lu: ", timer_jiffies, expires);

	if (idx < TVR_SIZE) {
		i = expires & TVR_MASK;
		vec = 1;
	} else if (idx < 1 << (TVR_BITS + TVN_BITS)) {
		i = (expires >> TVR_BITS) & TVN_MASK;
		vec = 2;
	} else if (idx < 1 << (TVR_BITS + 2 * TVN_BITS)) {
		i = (expires >> (TVR_BITS + TVN_BITS)) & TVN_MASK;
		vec = 3;
	} else if (idx < 1 << (TVR_BITS + 3 * TVN_BITS)) {
		i = (expires >> (TVR_BITS + 2 * TVN_BITS)) & TVN_MASK;
		vec = 4;
	} else if ((signed long) idx < 0) {
		vec = 1;
	} else {
		i;
		if (idx > 0xffffffffUL) {
			idx = 0xffffffffUL;
			expires = idx + timer_jiffies;
		}
		i = (expires >> (TVR_BITS + 3 * TVN_BITS)) & TVN_MASK;
		vec = 5;
	}

	printf("tv%d[%d]\n", vec, i);
}

void usage(void)
{
	printf("Commands:\n");
	printf("  s <value>    - Set timer_jiffies\n");
	printf("  <number>     - Set expires and call internal_add_timer\n");
	printf("  q            - Quit\n\n");

	return;
}

int main()
{
	unsigned long timer_jiffies = 0;
	unsigned long expires;
	char input[100];

	printf("Current timer_jiffies: %lu\n", timer_jiffies);

	while (1) {
		printf("> ");
		if (fgets(input, sizeof(input), stdin) == NULL) {
			break;
		}

		if (input[0] == 'q' || input[0] == 'Q') {
			printf("Exiting...\n");
			break;
		}

		if (strncmp(input, "s ", 2) == 0) {
			unsigned long new_jiffies;
			if (sscanf(input + 2, "%lu", &new_jiffies) == 1) {
				timer_jiffies = new_jiffies;
			} else {
				usage();
			}
			continue;
		}

		if (sscanf(input, "%lu", &expires) == 1) {
			internal_add_timer(timer_jiffies, expires);
		} else if (input[0] != '\n') {
			usage();
		}
	}

	return 0;
}
```

  ```
  ● 完美！现在我找到了完整的定义链：

  jiffies 的定义机制

  1. C语言声明 (include/linux/jiffies.h:85)：
  extern unsigned long volatile __jiffy_data
  jiffies;

  2. 实际存储变量 (架构相关，如
  arch/i386/kernel/time.c:76)：
  u64 jiffies_64 = INITIAL_JIFFIES;

  3. 链接脚本定义 (如
  arch/i386/kernel/vmlinux.lds.S:12)：
  jiffies = jiffies_64;

  关键点解释

  为什么这样设计？

  1. 32位与64位兼容：
    - 32位系统：jiffies是jiffies_64的低32位
    - 64位系统：jiffies就是完整的jiffies_64
  2. 链接脚本的作用：
  /* 32位小端系统 */
  jiffies = jiffies_64;      /* 指向低32位 */

  /* 32位大端系统 */
  jiffies = jiffies_64 + 4;  /* 指向高32位 */
  3. 实际内存布局：
  jiffies_64: [低32位][高32位]  (小端)
                 ↑
              jiffies

  jiffies_64: [高32位][低32位]  (大端)
                       ↑
                    jiffies

  这种设计的优势

  - 向后兼容：旧的32位代码仍可使用jiffies
  - 防止溢出：64位的jiffies_64不会溢出（约5亿年）
  - 原子性问题：32位系统读取64位值需要特殊处理（注
  释L925-927提到）
  - 透明访问：通过链接脚本，jiffies自动映射到正确
  位置

  这是一个巧妙的设计，通过链接器符号别名，让jiffie
  s和jiffies_64共享同一块内存！
  ```
