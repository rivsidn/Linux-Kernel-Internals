# TAP 用户态示例





                                 +------------------+                   +-----------------+
               内核发包          |                  |      READ         |                 |
         ----------------------> |                  | ----------------> |                 |
                                 |                  |                   |                 |
                                 |                  |                   |                 |
                                 |                  |                   |                 |
                                 |       TAP        |                   |      APP        |
                                 |                  |                   |                 |
                                 |                  |                   |                 |
               内核收包          |                  |      WRITE        |                 |
         <---------------------- |                  | <---------------- |                 |
                                 |                  |                   |                 |
                                 +------------------+                   +-----------------+




编译：

```bash
make
```

创建一个持久的 `tap0` 并启用它。第一个可选参数指定允许打开 TAP 的用户；第二个可选参数
为接口配置 IPv4/IPv6 地址：

```bash
sudo ./setup_tap0.sh "$USER" 192.0.2.1/24
```

终端一，程序打开 `tap0`，打印由内核交给它的完整以太网帧：

```bash
sudo ./tap_demo --iface tap0
```

终端二，产生可观察的二层流量：

```bash
ping -I tap0 192.0.2.2
```

`ping` 产生的 ARP 和 IP 帧会被 `tap_demo` 的 `read()` 读到。此时程序相当于接走了
原本应经 `tap0` 离开 Linux 的帧；真实 VPN 程序会在这里加密、封装后用 UDP/TCP 发送给对端。

下面的命令演示反方向。它构造一个 ARP 请求后对 TAP 文件描述符执行 `write()`：

```bash
sudo ./tap_demo --iface tap0 --inject-arp 192.168.100.2
```

这次 `write()` 不会直接让物理网卡发包。它把帧作为“从 `tap0` 收到的帧”注入内核；若将
`tap0` 加入网桥，网桥可依目的 MAC 将该帧继续转发给物理口：

```text
用户态程序 write(tap0) -> tap0 接收路径 -> br0 -> eth0 -> 真实网络
```

示例需要 root 或具备 `CAP_NET_ADMIN` 权限，并要求系统存在 `/dev/net/tun` 与 `tun` 内核模块。
