
## 历史背景

在早期的嵌入式 Linux（尤其是 ARM 平台）中，硬件信息是直接写在内核源码里的(通常在 arch/arm/mach-xxx/board-xxx.c 文件中).

这种做法的问题是:

1. 每换一块板子都要改内核源码并重新编译;
2. 代码难以维护:每个 SoC 或开发板都要有自己的 board 文件;
3. 硬件信息与内核强耦合，移植困难.

于是，Linux 引入了 设备树（Device Tree）机制 来解决这个问题.

## 工作流程

1. Bootloader(如 U-Boot) 加载内核镜像和 .dtb 文件;
2. 在启动内核时，将 .dtb 地址传递给内核;
3. 内核解析设备树，根据 compatible 字段匹配相应的驱动;
4. 驱动通过设备树节点读取资源信息(地址、中断、GPIO 等);
5. 驱动初始化硬件.


## 相关文件

| 文件类型 | 作用                                                                      |
|----------|---------------------------------------------------------------------------|
| `.dts`   | 主设备树源码（Device Tree Source）                                        |
| `.dtsi`  | 可被多个 `.dts` 引用的公共片段（include 文件）                            |
| `.dtb`   | 设备树二进制文件（Device Tree Blob），由 `dtc` 编译器生成，内核启动时加载 |
