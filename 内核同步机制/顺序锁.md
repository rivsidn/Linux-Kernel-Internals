
基于5.10.195 内核.

## 简介

一种reader-writer 之间的同步机制.

读执行的时候，写可以同步执行，读发现如果seq 有变化，则重新读取.

针对于读远大于写的情况.

## 序列计数器

### 初始化

```c
seqcount_t foo_seqcount;
seqcount_init(&foo_seqcount);

static seqcount_t foo_seqcount = SEQCNT_ZERO(foo_seqcount);
```

初始化为 0.

### 写路径

是否需要关调度实际上需要看情况.

```c
write_seqcount_begin(&foo_seqcount);
//...
write_seqcount_end(&foo_seqcount);

```

两个函数都递增seqcount，假设最初为 0，第一次递增为 1，第二次递增为 2.

奇数表示写正在执行; 偶数表示写完成.

### 读路径

```c
do {
        seq = read_seqcount_begin(&foo_seqcount);
        //...
} while (read_seqcount_retry(&foo_seqcount, seq));
```

- 获取seqcount，如果是奇数则循环等待写操作完成;
  如果是偶数则执行读取操作，如果数据变化则重新读取.
- 如果读侧是高优先级进程、中断，恰好抢占了写侧，这时候读侧可能会一直等待，导致livelock.


## 锁存序列计数器

即`seqcount_latch_t{}`，用于解决什么问题呢?

用于解决读侧一定会打断写侧的情况，如读侧在NMI 中.

此时如果读侧打断的写侧，通过上边的API ，写侧会一直循环，导致livelock.

这里不会死循环，会根据seq 是奇数还是偶数获取不同的版本，即锁存.
