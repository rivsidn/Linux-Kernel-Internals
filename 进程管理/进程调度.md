    ● enter_lazy_tlb() 函数的功能

    这个函数实现了惰性TLB（Lazy TLB）机制，用于优化切换到内核线程时的TLB管理。

    核心功能：

    标记CPU进入"惰性TLB"模式，表示当前CPU上运行的是内核线程，正在借用前一个进程的地址空间。

    具体实现（x86架构）：

    static inline void enter_lazy_tlb(struct mm_struct *mm, struct task_struct *tsk)
    {
    #ifdef CONFIG_SMP
        unsigned cpu = smp_processor_id();
        if (per_cpu(cpu_tlbstate, cpu).state == TLBSTATE_OK)
            per_cpu(cpu_tlbstate, cpu).state = TLBSTATE_LAZY;  // 设置为惰性模式
    #endif
    }

    TLB状态说明：

    1. TLBSTATE_OK (1)
      - 正常状态
      - TLB与当前进程的页表同步
      - 需要接收TLB刷新IPI（处理器间中断）
    2. TLBSTATE_LAZY (2)
      - 惰性模式
      - 运行内核线程，借用其他进程的mm
      - 不需要接收TLB刷新IPI

    为什么需要这个机制？

    1. 避免不必要的TLB刷新
      - 内核线程只访问内核空间，不访问用户空间
      - 借用的页表中用户空间部分对内核线程无意义
      - 其他CPU刷新该mm的TLB时，不需要通知运行内核线程的CPU
    2. 减少IPI中断
      - 当其他CPU修改被借用的mm时，会发送TLB刷新IPI
      - LAZY状态的CPU会忽略这些IPI，因为内核线程不使用用户页表
    3. 性能优化流程：
    用户进程A运行 (TLBSTATE_OK)
        ↓
    切换到内核线程 (enter_lazy_tlb → TLBSTATE_LAZY)
        ↓
    其他CPU修改A的页表 → 发送IPI → LAZY状态CPU忽略
        ↓
    切换到用户进程B (switch_mm → TLBSTATE_OK)

    实际效果：

    - 减少上下文切换开销：不刷新TLB
    - 减少IPI中断：LAZY状态不响应TLB刷新请求
    - 提高系统性能：特别是在内核线程频繁运行的场景

    这是Linux内核中一个精妙的优化，通过区分"真正使用mm"和"仅借用mm"两种情况，避免了大量不必要的TLB维护操作。
